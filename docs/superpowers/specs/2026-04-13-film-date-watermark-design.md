# 胶片日期水印工具设计文档

**日期：** 2026-04-13

**目标：** 构建一个可在 Windows 上运行的桌面工具，批量为当前文件夹及所有子文件夹中的 JPG/JPEG 照片添加胶片机 / 数码相机日期戳风格水印，支持预览、设置保存与加载，并可打包为单文件 `exe`。

## 1. 范围与约束

### 1.1 范围

工具需要支持以下能力：

- 选择多个 JPG/JPEG 文件进行批量处理
- 选择一个文件夹并递归处理所有子文件夹中的 JPG/JPEG 文件
- 默认使用 EXIF 拍摄日期生成日期水印
- 支持统一指定日期覆盖全部图片日期
- 支持两种日期输出格式：
  - `yy mm dd`，例如 `25 04 13`
  - `yyyy.mm.dd`，例如 `2025.04.13`
- 支持前缀、后缀、自定义颜色、自定义透明度
- 支持右下角自适应定位，保证文字不越界
- 支持预览界面，实时查看当前设置下的叠加效果
- 支持保存设置与加载设置
- 成功输出到 `dated_output`
- 失败输出到 `dated_failed`
- 默认保留原图、JPEG 质量、EXIF、文件修改时间等信息

### 1.2 约束

- 技术栈为 `Python + PySide6`
- 只支持输出到新目录，不支持覆盖原图
- 默认字体优先使用项目内的 [DS-DIGIB-2.ttf](H:/代码/胶片日期水印/DS-DIGIB-2.ttf)
- 软件界面采用单窗口布局，不使用向导式多步界面
- 浏览器可视化方案不纳入本项目范围，全部以桌面界面和中文文本交互为准

## 2. 用户界面设计

### 2.1 总体布局

主界面为单窗口，包含三个主要区域：

1. 顶部操作区
2. 左侧设置区
3. 右侧预览区

### 2.2 顶部操作区

顶部操作区包含以下按钮和状态信息：

- `选择多个文件`
- `选择文件夹`
- `开始处理`
- `打开输出目录`
- `保存设置`
- `加载设置`

同时显示：

- 当前已选图片数量
- 当前预览文件名
- 当前选择模式（多文件 / 文件夹）

### 2.3 左侧设置区

左侧设置区包含以下参数：

- 日期来源
  - `EXIF`
  - `统一指定日期`
- 缺少 EXIF 时改用文件修改日期
- 日期格式
  - `yy mm dd`
  - `yyyy.mm.dd`
- 前缀
- 后缀
- 字体路径
- 颜色
- 透明度
- 字体大小比例
- 安全边距比例
- 成功输出目录名
- 失败输出目录名

启用“缺少 EXIF 时改用文件修改日期”时，必须弹窗提示以下含义：

“启用后，缺少 EXIF 的照片将不再进入失败目录，而是使用文件修改日期生成水印。这样可能与实际拍摄日期不一致。”

### 2.4 右侧预览区

右侧预览区展示：

- 当前原图缩略预览
- 叠加日期水印后的预览图
- 当前最终日期字符串
- 日期来源说明
  - 例如：`EXIF: 2025:04:13 18:22:01`
  - 或：`统一日期: 2025-04-13`
  - 或：`文件修改日期回退: 2025-04-13 21:03:14`

预览规则如下：

- 选择多个文件时，默认取第一张图片作为预览源
- 选择文件夹时，递归扫描后取第一张可用 JPG/JPEG 作为预览源
- 用户修改任意设置时，预览实时刷新
- 预览仅在内存中生成，不写入磁盘

## 3. 文件选择与扫描规则

### 3.1 支持的导入方式

- 选择多个文件
- 选择单个文件夹

### 3.2 扫描范围

当选择文件夹时：

- 递归扫描当前文件夹及所有子文件夹
- 仅纳入扩展名为 `.jpg` / `.jpeg` 的文件，大小写不敏感

### 3.3 目录结构保留

输出时必须保留相对目录结构。例如：

- 原文件：`根目录\A\B\img.jpg`
- 成功输出：`根目录\dated_output\A\B\img.jpg`
- 失败输出：`根目录\dated_failed\A\B\img.jpg`

## 4. 日期来源规则

### 4.1 日期来源优先级

默认处理顺序如下：

1. 如果用户选择“统一指定日期”，则所有图片都使用该日期
2. 否则优先读取 EXIF 日期
3. 如果 EXIF 缺失：
   - 默认行为：跳过并输出到 `dated_failed`
   - 如果用户启用了“缺少 EXIF 时改用文件修改日期”，则改用文件修改时间

### 4.2 EXIF 字段优先级

读取顺序固定为：

1. `DateTimeOriginal`
2. `DateTimeDigitized`
3. `DateTime`

### 4.3 日期格式输出

支持两种格式：

- `yy mm dd`
- `yyyy.mm.dd`

最终绘制的水印文本计算规则：

`最终文本 = 前缀 + 格式化后的日期字符串 + 后缀`

## 5. 水印样式规则

### 5.1 字体

- 默认使用项目内字体 [DS-DIGIB-2.ttf](H:/代码/胶片日期水印/DS-DIGIB-2.ttf)
- 用户可改选其他 TTF 字体
- 若用户指定字体不可用，则处理失败并记录到失败结果

### 5.2 默认样式

- 默认颜色：`RGB(233, 110, 37)`
- 默认透明度：`75%`
- 默认日期格式：`yy mm dd`

### 5.3 字体大小

字体大小按图片宽度自适应，默认公式：

`font_size = max(12, int(image_width * 0.025))`

其中 `0.025` 暴露为可调参数“字体大小比例”。

## 6. 水印定位算法

### 6.1 目标

日期文字应稳定落在右下区域，同时永远不越界，不使用写死像素。

### 6.2 计算流程

1. 初始位置：
   - `x = image_width * 0.9`
   - `y = image_height * 0.9`
2. 测量实际文字宽高：
   - `text_width`
   - `text_height`
3. 计算安全边距：
   - `margin_x = image_width * 0.011`
   - `margin_y = image_height * 0.011`
4. 默认尝试位置：
   - `draw_x = x`
   - `draw_y = y`
5. 如果 `draw_x + text_width > image_width - margin_x`
   - 则调整为 `draw_x = image_width - margin_x - text_width`
6. 如果 `draw_y + text_height > image_height - margin_y`
   - 则调整为 `draw_y = image_height - margin_y - text_height`
7. 执行下限保护：
   - `draw_x = max(margin_x, draw_x)`
   - `draw_y = max(margin_y, draw_y)`

### 6.3 算法结果要求

- 水印始终位于右下区域
- 长前缀、长后缀情况下仍不得越界
- 极小尺寸图片下仍需保持边界安全

## 7. 图片读写与元数据保留

### 7.1 输出目录

在所选根目录下创建：

- `dated_output`
- `dated_failed`

目录名允许在设置中自定义，但默认值保持上述名称。

### 7.2 成功输出要求

成功处理的文件需满足：

- 生成带日期水印的新 JPEG 文件
- 保留原始 EXIF 信息
- 保留文件修改时间与访问时间
- 尽量保持原 JPEG 质量
- 原始文件不修改

### 7.3 失败输出要求

以下情况应进入失败目录：

- 不是有效 JPEG
- 图片损坏无法打开
- 默认模式下缺少 EXIF
- 字体加载失败
- 写出失败

失败文件应保留原目录层级，便于定位来源。

## 8. 批处理结果与日志

### 8.1 结果摘要

处理完成后，界面弹出摘要信息，至少包含：

- 成功数量
- 失败数量
- 缺少 EXIF 数量
- 输出目录位置

### 8.2 结果日志

生成 `process_report.csv`，记录以下字段：

- 原文件路径
- 结果状态：`success` / `failed`
- 日期来源：`exif` / `unified` / `mtime_fallback`
- 失败原因
- 输出文件路径

## 9. 设置保存与加载

### 9.1 存储格式

设置保存为 JSON 文件，建议默认文件名：

`watermark_settings.json`

### 9.2 保存内容

至少保存以下字段：

- 日期来源模式
- 统一日期
- 日期格式
- 前缀
- 后缀
- 字体路径
- 颜色
- 透明度
- 字体大小比例
- 安全边距比例
- 是否启用文件修改日期回退
- 成功输出目录名
- 失败输出目录名

## 11. 测试策略

本项目优先测试核心逻辑，不对桌面 UI 做复杂自动化。

### 11.1 必测项

1. 日期格式化测试
   - 验证 `yy mm dd`
   - 验证 `yyyy.mm.dd`
2. 日期来源测试
   - 验证统一日期优先
   - 验证 EXIF 字段回退顺序
   - 验证缺少 EXIF 时的失败路径
   - 验证缺少 EXIF 时的文件修改日期回退路径
3. 定位算法测试
   - 正常尺寸图片位于右下
   - 极小图片不越界
   - 长前后缀文本不越界
4. 输出路径测试
   - 验证递归目录结构保留
5. 设置读写测试
   - 验证保存后再加载内容一致
6. 批处理结果测试
   - 验证成功、失败、回退来源都能写入报告

## 12. 打包方案

### 12.1 打包工具

使用 `PyInstaller` 打包 Windows 单文件可执行程序。

### 12.2 目标命令

推荐命令方向：

`pyinstaller --noconfirm --onefile --windowed app.py`

### 12.3 资源处理

- 默认字体文件需一并打包
- 若用户手动指定了外部字体路径，则优先使用用户字体

## 13. 非目标

以下内容不在本次实现范围内：

- 覆盖原图
- 支持 PNG、HEIC、RAW 等非 JPEG 格式
- 自动识别人脸或复杂智能避让
- 多种水印模板系统
- 多语言界面

## 14. 成功标准

项目实现完成后，应满足以下标准：

- 在 Windows 上可正常启动并运行
- 能批量处理多文件或递归处理文件夹
- 默认使用 EXIF 拍摄日期
- 支持统一日期与缺少 EXIF 的修改日期回退
- 预览图与最终输出的定位和样式一致
- 成功与失败文件正确分流
- 设置可保存与加载
- 可打包为单文件 `exe`
